# v0.2.0 — Panel workspaces and interaction safety

Local release candidate; not yet published.

## Changes

- Reorganize panel navigation into Overview, Gateway, Access, Monitoring and System workspaces, with responsive navigation and a command palette.
- Apply shared branded surfaces, focus states, density and language preferences while preserving existing artwork and provider icons.
- Improve mobile resource layouts, filtering, pagination, account inspection and quota-window explanations. Keep unknown quota values distinct from zero and grouped model-family counts distinct from flat model totals.
- Add shared review dialogs for consequential actions, duplicate-operation guards and dirty-editor navigation protection.
- Keep unresolved banked-credit redemption attempts fenced across component remounts and reloads within the same tab session. A lost response is not proof of failure; this is not a server-side reconciliation mechanism.
- Rework Connect Tools into protocol-specific workspaces with placeholder-first previews, explicit secret-copy confirmation and bounded request lifecycles.
- Improve login, OAuth cancellation, read freshness and polling behavior without changing server authentication contracts.

## Compatibility and upgrade scope

This candidate changes panel source and its tests only, plus these release notes. Server API implementations, request contracts, authentication, database schema and dependency lockfile are unchanged. Existing panel route paths remain registered; navigation labels and presentation change without introducing breaking redirects. Existing provider capabilities and disabled build features are not enabled by this UI update.

The workspace package manifests remain at `0.1.0`, consistent with the existing tag-driven image workflow. That workflow derives the application image version from a release tag or source SHA rather than the workspace package version. No npm publication is enabled.

## Reproducing confirmation and credit browser checks

The retained `apps/panel/tests/banked-remount.browser.mjs` and `apps/panel/tests/confirmations-credits.browser.mjs` use the public `tests/confirmations-credits.fixture.html` entry and existing synthetic React fixture. No private gallery, images, credentials or live API is required. From `apps/panel`, with dependencies installed:

```sh
NODE_ENV=development bun --no-env-file run dev --config tests/redesign-vite.config.ts --host 127.0.0.1 --port 5207 --strictPort
# In another shell, set PLAYWRIGHT_MODULE to an installed Playwright ESM module
# and CHROMIUM_PATH to its installed Chromium executable, then run:
STYX_TEST_BASE_URL=http://127.0.0.1:5207 node tests/banked-remount.browser.mjs
STYX_TEST_BASE_URL=http://127.0.0.1:5207 node tests/confirmations-credits.browser.mjs
```

Use an unused loopback port and update both the server and `STYX_TEST_BASE_URL` together. The runners block other origins and intercept all API requests, including synthetic redemption POSTs; no real credit is spent. Screenshots default to ignored `evidence/browser` relative to the repository (override with `REDESIGN_EVIDENCE`). These two checks are standalone component-fixture checks, not an assertion that every browser script or authenticated route has been freshly accepted.

## Verification boundaries

Automated local fixture tests are not live-provider certification, native-client certification or exhaustive accessibility acceptance. No inference or credit redemption against a real upstream service is part of local release preparation. Manual assistive-technology and physical-device acceptance remain open. Container build/smoke and protected publication-hygiene CI must be verified against the eventual approved source commit before release; a source archive is not a container image.
