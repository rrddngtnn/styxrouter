# Augment API

`augment-api/<canonical-tenant-model-id>` is a separate native provider. Its public alias is also `augment-api`; existing `auggie` / `aug` remains the local CLI provider.

## Credentials and onboarding

In API Keys → Augment API, supply the private API credential and the administrator-provided tenant API URL. Only HTTPS origins matching `<tenant>.api.augmentcode.com` are accepted (no paths, credentials, query strings, fragments or nonstandard ports). Every credential-bearing discovery, validation and generation call uses public-only A/AAAA validation and a fresh DNS-pinned native HTTPS connection with the original Host/SNI and normal certificate verification. Mixed/private/reserved answers and all redirects reject. Effective environment/application proxy and HTTP/relay contexts reject with `unsupported_augment_proxy`; there is no generic-fetch or silent direct fallback. Generic custom gateway overrides are not used. JSON import accepts `{ "provider": "augment-api", "accounts": [{ "token": "<private token>", "apiUrl": "https://<tenant>.api.augmentcode.com" }] }`. Never send credentials in chat. Existing credential encryption, management authentication and caller connection ACLs are retained. An imported matching token cannot be rebound to another tenant.

Credential validation and account model synchronization POST `{}` to `/get-models`; generation POSTs the native `/chat-stream` payload. No inference occurs during validation. Discovery cost has not been independently verified. Synchronization is account-scoped, explicit (not automatically scheduled here), preserves last-good state on failed/malformed/empty discovery, and invalidates existing catalog/connection caches. Generation additionally discovers the selected tenant's exact enabled registry IDs before dispatch. Unknown or disabled IDs are rejected rather than treating unknown catalog as entitlement. CLI aliases such as `haiku4.5` are not rewritten.

## Supported surface and honest limits

Text, multi-turn text history, caller-executed function tools and tool results, reasoning output, streaming NDJSON → SSE, and accumulated JSON are implemented. Tool IDs are preserved; the router never executes tools. Conversations are stateless unique dispatch IDs, not caller-controlled shared sessions. Missing native usage is omitted by the adapter; the surrounding router may separately estimate usage. No native budget, temperature, sampling, tool-choice or structured-output field has been established in the pinned published SDK payload builder. Explicit unsupported fields return structured HTTP 400 before native dispatch. Do not interpret omission as unlimited output or guaranteed low cost. The ordinary Chat Completions omission path does not inject a 32768-token fallback. Anthropic callers that require `max_tokens` cannot use this adapter until a supported budget contract exists.

Explicit `min_tokens`, `min_p` and `logit_bias` are unsupported and rejected, not silently dropped. Routing aliases and declared nested combo targets are checked before caller accounting, quota preflight or account last-use mutation; a mixed combo containing Augment rejects unsupported options rather than falling back. No static model capacities/prices are asserted. Public model metadata advertises unsupported output-token limits and sampling, not fictitious capacity. No OAuth flow, cookies, local session-file import, OpenAI upstream shim, CLI fallback or internal tool loop is provided. NDJSON is decoded incrementally with fatal UTF-8 checks, 1 MB frame / 16 MB total bounds and cancellation. Missing/unknown/error terminal reasons fail closed. Authentication, entitlement, quota and transient HTTP errors are typed; upstream bodies are not exposed.

The protocol review adds account-scoped persisted-catalog preselection, durable connection/status/key/tenant revalidation before discovery and again before generation, strict numeric terminal enums and final-frame ordering, and incremental tool argument accumulation. A pre-send read cannot atomically prevent a later concurrent revocation. Unknown inventories still use fresh discovery. Native dispatch failures return directly without account/CLI/model fallback or account-health mutation; automatic transient retry is deliberately not claimed. Mounted fixtures cover omitted-budget Chat Completions and Responses, and reject required-budget Messages before network. Browser fixtures exercise the actual original-panel provider form at mobile/desktop light/dark with fake credentials and intercepted local-only requests. These are separate from live acceptance.

Synthetic mounted-Hono acceptance is not live upstream acceptance. Live tenant authentication, discovery, inference, usage and billing remain UNVERIFIED; availability of this adapter is not proof of account entitlement or free access. Real tenant calls require separately authorized credentials and explicit live-call authorization. Independent candidate review covers transport policy, mounted shared-account ACL checks, a separate-process caller revocation, per-send caller/model/connection revalidation and consistent management/public capability disclosure. A pre-send read does not atomically fence a later policy commit; session-authenticated management retains its existing admission contract. Protocol support is bounded to text/function-tool Chat Completions and omitted-budget Responses; required-budget Messages is explicitly unsupported. Declared Augment targets under pipeline, parallel, fusion, chaos, context-relay or other non-priority/non-round-robin strategies reject with HTTP 400 before account selection. Nested declared targets inherit that restriction. Hook/task/web-search/reasoning reroutes into Augment reject before combo availability selection; arbitrary plugin-generated or later virtual-auto targets are not established as supported. This is a provider-specific restriction, not relaxed route authorization. Simple priority/round-robin admission is not proof of every retry/race permutation. Release artifact and deployment evidence are recorded separately; focused synthetic tests alone do not establish live acceptance.
